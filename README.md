# N2SysServerManager2

Vue 3 + Element Plus 前端，FastAPI + SQLAlchemy 后端，AsyncSSH 后台同步。

## 本地启动

需要 Python **3.10+**、Node.js **20+**（本次验证使用 Python 3.14 / Node 24）。macOS 自带 Python 3.9 不支持本项目部分类型语法，请使用新版 `python3`。

```bash
# 在仓库根目录
python3 -m venv .venv
.venv/bin/python3 -m pip install -r backend/requirements.txt
cp backend/.env.example backend/.env  # 已有 .env 时不要覆盖
```

编辑 `backend/.env`：

- `SECRET_KEY`：至少 32 字符的私密随机字符串，可用 `python3 -c "import secrets; print(secrets.token_urlsafe(48))"` 生成。
- `INITIAL_ADMIN_PASSWORD`：至少 12 字符，仅空数据库首次启动创建 `admin` 时使用。已有数据库不会重置管理员密码。
- `ACCOUNT_INITIAL_PASSWORD`：新建**远端 Linux 账号**的初始密码，启动时读取一次，未配置时为 `Qwe123!@#`。与平台管理员的 `INITIAL_ADMIN_PASSWORD` 不同；改配置后需重启，已有账号不会批量改密。
- `DATABASE_URL`：默认 `sqlite:///./test.db`，相对于后端启动目录。
- `SYNC_ENABLED=false`：开发环境保持关闭，防止修改真实服务器账号。
- `GATEWAY_KEY_SYNC_ENABLED=true`：启用同步时，检查并生成网关用户的个人 SSH 密钥，仅同步公钥；见下方说明。全局同步关闭时此项不会触发任何 SSH。

两个终端分别运行：

```bash
cd backend
../.venv/bin/python3 main.py
```

```bash
cd frontend
npm ci
npm run dev -- --host 127.0.0.1
```

访问 Vite 输出的地址（通常 `http://127.0.0.1:5173`）。前端 `/api` 代理到 `127.0.0.1:3876`，后端 API 文档为 `http://127.0.0.1:3876/docs`。

`backend/.env` 是本地私有配置，不纳入 Git。首次准备环境请自行生成随机 JWT 密钥和初始管理员密码，设置文件权限为 600；仓库只提供无真实凭据的 `.env.example`。建议在确认配置前保持 AI 未配置、SSH 同步关闭。

## 新建服务器账号的初始密码

```dotenv
# backend/.env：用引号保留 # 等特殊字符，修改后重启后端
ACCOUNT_INITIAL_PASSWORD='Qwe123!@#'
```

- 平台启动（FastAPI lifespan）时读取并校验，SSH 任务只使用启动快照，不逐请求读取环境变量。留空是配置错误；未设置才使用上述默认值。换行、NUL 和冒号不允许。
- 密码通过加密 SSH 通道的标准输入传给远端 `chpasswd`，不会拼到命令行、写入后端日志/错误或下发前端。需要目标机具备 `useradd`/`chpasswd`、GNU `timeout`/`stat`、`flock`，以及后端 SSH 服务账号的非交互 sudo 权限。
- 新建流程用 `/var/lib/n2sys/account-passwords` 中 root 专属标记和非秘密 GECOS 来源标识，支持“用户创建成功但密码设置失败”后的重试；不会把同名旧账号当作新账号改密。请勿手工更改尚未完成创建账号的 GECOS/标记。
- 已完成初始化的账号不重设密码；撤权后重新启用仍沿用安全的密钥登录恢复策略，不自动解锁历史密码。是否允许 SSH 密码认证仍由目标机 `sshd`/PAM 配置决定。
- **统一默认密码存在共享凭据风险**，生产建议在私有配置中覆盖，并让新用户尽快改密。历史 `123456` 或其他弱密码不会被此次修改自动修复。

## 网关用户个人 SSH 公钥自动同步

学习旧部署的使用流程后，本地增加了安全重实现，**不是读取/使用管理平台 n2sys 服务账号的备份私钥**。

- 只有活跃用户、网关机器、允许登录且账号状态已经为 `ACTIVE`（完成远端账号同步）的组合才会执行。先创建账号/配置登录，再处理个人密钥。
- 使用目标用户身份执行 `sudo -n -H -u 用户`，读取或首次生成其主目录下 `.ssh/id_ed25519`。已有私钥不会被替换；缺少 `.pub` 时从私钥导出公钥。孤立公钥、不匹配密钥、加密私钥无法非交互读取等情况明确报错，等待处理。
- **私钥一直保留在网关，不下载、不写数据库、不通过 API 返回。** 后端只接收校验后的单行 Ed25519 公钥，按类型和 key 数据去重（不依赖注释），追加至用户公钥配置，不覆盖手工公钥。
- 新增公钥会把该用户所有允许登录账号标记为需同步，包含正在 `UPDATING` 的账号，避免正在运行的旧任务漏掉新 key。只影响已授权账号，不自动申请新机器权限。
- 首次成功后约 **4 小时**复查，失败约 **5 分钟**后重试。生成/读取前后均重新核对用户和账号授权状态；与资料更新共享用户锁，数据库事务不跨 SSH 等待。
- 网关需具备 `timeout`、`flock`、`ssh-keygen`、`getent`、GNU `stat`/`realpath`/`ln` 等工具，以及后端同步服务账号的非交互 sudo 授权；不自动安装工具。目录和文件存在符号链接/硬链接/所有权风险会拒绝操作，避免以 root 跟随用户路径。特殊 home 布局请先验证兼容性。
- 此功能有隐私/信任含义：持有网关上个人私钥即可访问该用户已经授权并接收了公钥的机器。它不是 key 轮换或吊销系统；删除/泄露旧 key 仍需管理员核对并撤销，关闭此开关不会移除已经分发的公钥。

```dotenv
# 需要全局SYNC_ENABLED=true才会工作；本地仍保持全局false。
GATEWAY_KEY_SYNC_ENABLED=true
```

后台错误在 Summary 中以 `gateway-key`、账号 ID 和明确原因展示；密钥任务沿用受跟踪任务、连接清理及等待关闭机制。关闭该开关可单独停用网关密钥功能，不影响其他采集/账号同步。

## 用户审核、身份显示与登录体验

- Management 用户表增加 **Real Name**；待审核注册增加 **Reject Registration**，必须二次确认。后端只允许管理员拒绝非管理员 `VERIFYING` 用户，有关联服务器账号或活跃使用登记时返回冲突，不能用删除数据库记录的方式绕过远端撤权。正常待审核申请与登记在同一事务清理。已激活用户请使用原有毕业/撤权流程。
- Summary 增加 **Linux Account Name**，明确区分显示姓名、平台用户名与 Linux 登录名。
- 受保护页面遇到未抑制的 401 时跳转登录并提示会话过期；403 不跳转，登录/注册页的预期匿名401不干扰页面。登录后仅允许返回白名单内部路径，不接受外站/协议相对地址/嵌套跳转。
- Profile 保存前提示“未修改”或“请输入当前密码”，不发送无意义请求；所有变更仍由后端校验当前密码。公钥修改还带有从 `/user/me` 读取的 `public_key_revision`：后台网关已追加新 key 或其他会话已改动时返回409，不覆盖较新密钥。请先复制保存自己的草稿，整页刷新读取最新列表，核对合并后再提交。旧客户端修改公钥也需要此版本字段；仅更改其他资料而公钥未变时不强制要求。
- Profile 的姓名/邮箱/公钥及申请页的机器选择/用途/sudo选项，可在**同一标签页内存**中为同一账号恢复；密码/token不保存。换账号或显式退出会清理，刷新整个浏览器页面后草稿不会跨刷新恢复。错误提示仍保留，敏感表单请勿在共享浏览器中长期停留。

## 设备 AI 助手

在 **Servers（设备筛选）** 和 **Devices（连接视图）** 右下角打开「AI · 问问设备」。支持多轮对话、清空、收起、失败保留问题重试、手机宽度布局。回答作为纯文本渲染，不执行 HTML。

在后端 `.env` 配置后重启：

```dotenv
AI_BASE_URL=https://your-openai-compatible-service.example/v1
AI_API_KEY=your-private-key
AI_MODEL=your-model-name
AI_TIMEOUT_SECONDS=45
```

- Base URL 包含服务所需的 `/v1` 前缀，**不包含** `/chat/completions`；后端自动追加该路径。
- 接口使用 OpenAI Chat Completions 格式，非流式 `POST`，可使用本地兼容服务；不需要鉴权的本地服务可留空 API Key。生产环境建议 HTTPS。
- 前端仅访问 `GET /api/ai/status`、`POST /api/ai/chat`，没有密钥，也不能指定上游地址或覆盖 system 指令。
- **只有登录用户主动发送问题才调用 AI**。会向管理员指定的服务发送本系统登记的服务器主机/端口、状态、OS/内核、标签、CPU/内存/GPU及显存/磁盘/网卡速率等硬件快照、交换机名称和端口数；不发送用户列表、公钥、密码、IPMI。
- 当前系统没有多组/租户模型，「我们组」指这个实例中的全部登记设备，范围与已登录用户能查看的设备清单一致。状态和硬件均为最近一次采集结果，未采集或陈旧的硬件会明确标记，不能当作实时可用性。
- 每次问题重新构建设备快照。支持 20 条历史消息（单条用户消息最多 4000 字符、合计 20000）；清单上限 60000 字符，超限明确报错，不截断后假装完整。每用户最多 1 个并行请求，进程最多 4 个。生产配额/费用限制还应配置在上游服务或反向代理。
- 未配置、连接失败、超时、上游鉴权/限流/模型错误、无效回答都有明确提示，不透传可能包含敏感信息的上游响应正文。
- AI 仅用于查询，没有 SSH、修改设备或授权能力。第三方模型仍可能出错，重要信息请核对设备详情。

## 硬件信息采集

后台 SSH 同步增加只读硬件采集，设备列表、机器申请页、服务器详情共享同一份结构化快照：

| 类别 | 采集内容 | 口径 |
| --- | --- | --- |
| CPU | 型号、插槽数、物理核数、逻辑线程数 | 系统可见拓扑，不保证等同机箱最大配置 |
| 内存 | 总量、采集时可用量 | 字节存储，前端 GiB/TiB；不是实时监控 |
| GPU | 型号、厂商、显存、PCI 地址 | 型号和显存分开处理；驱动缺失时不能把未知显存填成 0 |
| 磁盘 | 块设备名、型号、原始容量、类型、旋转介质标志 | 不重复相加分区；不是文件系统剩余空间，也不能把 RAID/多路径容量简单相加 |
| 网卡 | 接口名、MAC、PCI 地址、链路状态、速率 | Mbps 存储；链路关闭/工具不支持时明确未知，不代表速率 0 |

- 跟随设备同步周期（正常约每小时）采集，管理员在设备详情可以请求提前刷新。不会为了采集自动安装驱动、软件或改服务器配置。
- 目标系统为 Linux：CPU 使用 `lscpu -J`，内存读取 `/proc/meminfo`，磁盘使用 `lsblk -b -J`；GPU 结合 `lspci`/PCI sysfs、NVIDIA `nvidia-smi`、AMD DRM 显存信息。网卡读取 sysfs，支持以太网及 InfiniBand（含没有 IPoIB 接口的原生端口）。缺工具/驱动会报对应项失败，不影响整台机器的其他项。
- 单命令约 5 秒、每类约 8 秒截止；硬件失败不会导致每 30 秒无限重试缺失工具。特殊硬件/驱动及虚拟化透传结果仍需在实际目标机核对。
- 每类分别保存 `status/data/error/collected_at/checked_at`，缺少工具、权限不足、驱动错误、解析失败都会给出原因。某项失败不阻止其他硬件和登录记录采集。
- 某项完全失败保留其上一次成功值及成功时间，页面明确标为旧数据；拿到部分设备信息时显示该次部分结果并说明错误；正常快照超过两小时也标为陈旧。连接失败不会让旧值假装刚刚采集。
- AI 上下文已包含上述硬件数据和采集状态，不发送使用者姓名或申请用途。AI 不应把未知值当成 0，或者凭规格断言机器空闲。

## 独立申请机器与使用登记

进入导航中的 **申请机器**（`/apply`），设备列表和 Profile 也提供入口。设备 SSH 状态仅供参考，不阻止登记，也不保证当前能连接；权限生效仍取决于后台同步。

1. 搜索主机名、标签或硬件信息，勾选一台或多台设备（最多 50），填写用途，可勾选需要 sudo。批量请求在一个数据库事务中校验/保存，某台冲突时不会悄悄只申请其他机器。
2. **已有足够访问权限**的用户直接登记使用；没有权限、权限已撤回或需要提权时进入 Management 待审批列表。管理员直接登记时可立即授权，已有 sudo 不会因未勾选而被降权。
3. 审批通过后变为“使用登记中”。这是已获批准的使用意向，SSH 账号同步仍可能待完成或失败，应结合 Summary 的同步状态核对。
4. 所有登录用户都能看到每台设备的**使用登记者姓名、开始时间、最近确认时间、待审批数、访问账号数**。自己的申请用途仅自己和审批管理员可见。
5. 点击 **确认仍在使用** 更新确认时间；点击 **结束使用登记** 只结束自己的登记，**不撤销 SSH、不杀进程、不取消账号**。待审批申请可取消。结束后可以再次勾选登记使用。
6. 系统管理员撤销账号/用户毕业，或自动回收账号时，会同步结束有效使用登记。管理员 API 可以结束他人登记；普通用户不能修改他人的登记。
7. 使用中的非网关机器可单独点击 **申请 sudo 权限**，不用结束登记。填写原因后进入原 Management 审批列表（类型为 sudo 权限升级），可取消。批准只修改 sudo 和待同步状态，不重置使用开始/确认时间或最后活动时间。拒绝/取消保留原登记；结束登记/撤权会清理该类待审批申请。重复、替他人申请、已具备sudo、权限已撤回或登记已结束均会被拒绝。
8. 最近 30 天明确登记/确认仍在使用的账号，不会仅因缺少 SSH 登录活动被自动闲置回收，以免长训练任务误撤权。超过 30 天没有确认则恢复原有回收判断，登记不会凭时间直接假装结束。请使用者定期确认，并与其他人沟通。

**重要区别：**“无人登记”不等于机器物理空闲；“有访问账号”不等于有人正在用。此功能不是排他预约、资源配额或实时 GPU/进程监控，允许同一机器有多名使用者。已有历史账号不会被自动转换成使用登记；第一次上线请大家主动勾选正在使用的机器。旧申请审批后会补上使用登记。

新建 `server_hardware`、`device_usage` 和 `application_purpose` 三张表，由后端启动时 `create_all` 仅增量创建，**不修改原表字段或批量转换旧数据**。当前登记表保留每个用户/服务器组合的最新一轮状态，不是完整历史审计。生产更新前仍须备份数据库。

## 隐藏长期未使用的管理员账号

首页 **Summary** 原先只有登录时间颜色标记，没有隐藏开关。现在提供：

- 默认隐藏超过 **30 天**未登录对应服务器的**系统管理员账号**；天数可调 1–3650。
- 这里的管理员指 `User.is_admin`，不是仅拥有某台服务器 sudo 的普通用户。
- **每次进入或刷新 Summary 均默认开启隐藏**，旧浏览器保存的 `hide:false` 不再覆盖。可点击「显示全部管理员」临时查看；仅天数偏好按当前用户保存在浏览器。
- 未知/无效日期不隐藏；无账号或所有账号被隐藏的服务器仍保留一行。
- **只影响显示，不撤权、不删除数据**。与原有「普通用户非网关账号 30 天自动回收」逻辑独立。
- 沿用现有 `last_login_date` 字段，实际口径为**最后活动时间**：正常退出采用退出时间，仍在线采用平台当前时间，宕机/缺失退出记录采用已知登录时间。新建或重新授权时也会设置当前时间作为宽限期，并非一定代表真实 SSH 登录。旧数据没有单独的“从未登录”标记。

### 时间识别修复

旧实现的 `last -F -R | head -1 | awk '{print $10, $11, $12, $13}'` 固定取列，在 crash/down/no logout 等状态下会选错；第一条最近记录也不一定是仍在线的会话。现在：

1. 先用 `who` 精确匹配用户名，识别所有当前在线会话；否则读取 `LC_ALL=C TZ=UTC last -w -R --time-format iso -- 用户名`，解析带时区的 ISO 时间和会话状态，不再靠列号、月份语言或远端 `date -d` 猜测。
2. 无记录返回未知，不伪造 1970 年或今天零点。命令不支持/缺失、权限错误、无效日期、退出早于登录、超前超过 5 分钟的记录会明确报错。
3. API 的 `lastLogin`/`last_login_date` 现在返回带 `Z` 的 UTC 时间，前端按浏览器时区显示与计算；旧无时区 API 字符串不再被前端猜测。
4. 为兼容旧库，数据库仍保留**后端运行环境本地时间的无时区存储格式**，采集 UTC 和 API UTC 在边界转换；请保持生产后端原时区稳定。旧版已写错的数据（特别是远端时区不同的记录）无法无损自动判断来源，未做猜测性批量迁移。发现历史未来时间会提示人工核对；修复后可手动请求刷新。
5. **普通用户的 30 天自动回收必须有最近 5 分钟内成功采集的、非空活动记录**，且授权时间未被并发修改。刚启动、SSH/解析失败、记录被轮转后不可用时不根据旧库盲目回收。无可用记录的账号需要人工审核，不认定为“从未登录”。正常每小时采集后、下一次调度才会执行满足条件的回收。

解析口径核对了 [util-linux last 源码](https://github.com/util-linux/util-linux/blob/master/login-utils/last.c) 的 ISO 时间及 `still logged in`、`crash`、`down`、`gone - no logout` 状态。优先使用 util-linux `last --time-format iso`；另增加严格的 `lastlog` 兜底：成功读取但无记录，或 last 命令非零退出时，尝试 `LC_ALL=C TZ=UTC lastlog -u 用户`。只接受精确用户名、标准表头、带 UTC/数字偏移的完整日期，按日期后缀解析而不是固定端口/主机列。有效非空 last 结果不再额外合并 lastlog；last 的无效/未来日期不会被 lastlog 掩盖，SSH超时/传输失败也不当作空记录。

`lastlog` 显示 Never logged in 时返回未知；成功空 last 且 lastlog 未安装（127）也返回未知。两个命令都不可用或 lastlog 格式异常会报告原因，不猜测时间、不伪造1970年、不据此自动回收。`who` 仍在线的判断和平台 UTC 当前活动时间优先。

## 错误可见性

- HTTP 失败、网络失败、超时、JSON 解析失败及前端运行时异常统一进入右上角常驻错误面板，必须手动关闭；带原因、请求路径、HTTP 状态和请求编号。表单校验同时在对应表单提示。
- 失败写请求会中断后续操作，不再提示假成功、关闭编辑框或刷新丢失输入。加载状态通过 `finally` 恢复。
- 后端统一处理校验错误、数据冲突、数据库不可用、意外内部错误。意外异常不把堆栈/SQL/凭据暴露给前端，提供请求编号用于查日志。
- 管理员 Summary 每 30 秒查询 `/summary/sync-errors`，显示后台 SSH/账号/采集错误。原因使用受控分类（认证失败、主机密钥不受信任、超时、sudo/文件权限、缺少命令等），不展示原始 SSH stderr。重试成功清除错误；最近 200 项保存在**进程内存**，重启后不保留，日志另存 `logs/`。

## 升级与 SSH 注意事项

**更新现有部署前先备份数据库和私有 `.env`。本次新增三张表，不修改旧表列；新表在启动时自动创建。**

1. 原仓库跟踪了占位 `.env`，现在改为只跟踪 `.env.example`。升级时注意恢复自己的 `.env`，不要把真实密钥提交到 Git。
2. 不再接受公开/过短 JWT 密钥；更换 `SECRET_KEY` 会使旧登录失效。空库不再创建 `admin/admin`。已有弱密码请主动修改。
3. Web 密码改用加盐 PBKDF2-SHA256；旧 SHA256 哈希在成功登录后自动升级。`/user/me` 不再返回密码哈希；未激活/已毕业用户的旧 token 也不能访问接口。
4. SSH **默认验证主机密钥**，需为后端运行账号配置目标和跳板机的可信 `known_hosts`、SSH 用户和私钥（沿用 AsyncSSH/OpenSSH 配置）。可指定 `SSH_KNOWN_HOSTS=/path/to/known_hosts`。仅隔离测试场景可显式设置 `SSH_INSECURE_SKIP_HOST_KEY_CHECK=true`，不建议生产使用。
5. 确认配置后设置 `SYNC_ENABLED=true` 并重启。同步每约 30 秒调度，正常设备约每小时采集；刷新按钮真正排队请求采集，而不是立即假报刷新完成。服务应使用**单个 worker**，避免多个后台调度器重复执行。
6. 新建 Linux 账号使用启动时的 `ACCOUNT_INITIAL_PASSWORD`，缺省 `Qwe123!@#`；已有活跃远端账号的密码**不会自动批量替换**，请管理员审计历史默认密码。
7. 撤权会锁定/过期账号、设置 nologin 并移除 sudo 组，阻止新登录；**不会强制终止现有会话**，也不能清除用户额外手工配置的 sudoers 规则。操作异步完成，请关注同步错误。
8. 为兼容手工维护的 SSH key，仍合并已有 authorized_keys，修改个人公钥**不会删除旧 key**。丢失/泄露的旧 key 需管理员在目标服务器单独移除。
9. Linux 账号名校验为 `[a-z_][a-z0-9_-]{0,31}`；旧库中的不合法名称会阻止该账号同步并报错，需要先核对修复。
10. SQLite 外键约束现在生效；旧数据的悬空连接会明确返回 409，不再退出整个后端进程。已有数据不自动做破坏性清理，遇到冲突应备份后检查修复。

本次还修复了退出 cookie 未删除、个人页错误接口/身份来源、申请冒用其他用户、重复申请、最后管理员保护、网关权限规则、接口模糊匹配误连、连接/交换机部分提交、后台日志拼接导致同步停止、连接和数据库会话泄漏等问题。
